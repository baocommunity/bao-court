## Fixes

### 1+2. Complaint protocol hardening
Files: `types.ts`, `dkgMessages.ts`, `independentDkg.ts`.
Design: `docs/COMPLAINT-PROTOCOL.md`.

- `DkgComplaint.encryptedShareEventId` is now **required** (the kind 39003
  share event the victim received — the possession anchor).
- `parseDkgComplaintEvent` rejects any event whose signed author is not the
  victim pubkey, self-accusations, malformed pubkeys, and missing/malformed
  anchors — never throws, returns `null`.
- `addComplaint()` now returns `boolean` and admits only roster-bound,
  author-bound, deduplicated, budgeted complaints; local-victim complaints
  additionally require the accused to have actually delivered a share to
  this session.
- `resolveComplaints()` settles each (victim, accused) pair once: verified
  revealed share or valid defense **exonerates** the accused (complainer
  surfaced via `getFalseComplaints()` for slashing); invalid share or bogus
  defense disqualifies; disqualified complainers' complaints are void.
- `getPhase()` no longer reports `'complaint'` once every admitted
  complaint is resolved (`hasPendingComplaints`).

Security rationale: an honest juror now reveals at most one polynomial point
per genuinely misbehaving peer; under an honest majority (`m+1 ≤ t`) the
revealed points stay below threshold, so polynomial/group-secret recovery
and the zero-cost ceremony DoS are both closed.

### 3. `restoreFromBackup` full recomputation battery
File: `independentDkg.ts`.

Restore now re-derives everything from the backup's VSS commitments with the
same curve functions the live DKG uses:
- consistent array counts, indices exactly `1..n` in order, per-participant
  commitment counts equal to the session threshold;
- group key recomputed as Σ of the constant commitments and compared to the
  backup's claim (compressed full-point);
- every verification share recomputed and compared to the claimed x-only
  share;
- the local share checked by **full point** (parity-exact), rejecting the
  negated share `n − s` that an x-only check would certify.

Empirical before/after: a poisoned self-consistent backup under a different
group key was accepted before the fix (`restoreFromBackup → true`) and is
rejected after (`false`).

### 4. Strict legacy NIP-59 unwrap
File: `nip59.ts`.

`unwrapProtocolEvent`/`unwrapProtocolEvents` now run the same gate as the
signer-backed path in `courtSigner.ts`: recipient `p` tag, seal Schnorr
signature (reconstructed plain object, cache-trap safe), seal-author ===
rumor-author, and rumor-id recomputation. NIP-59 rumors are intentionally
unsigned, so the rumor is bound by id recomputation only; the seal signature
covers authorship. Anything failing any check returns `null`.

### 5. Complaint-phase liveness
File: `independentDkg.ts` (`getPhase`/`hasPendingComplaints`). Documented in
README §13.

### 6. Test timeout hardening
Files: `__tests__/courtFuzz.test.ts` (60 s), `__tests__/independentDkg.test.ts`
(120 s on the 3-of-5 DKG and networked-refresh tests, 60 s on restore).

### 7. Deterministic seeded-scalar counter
File: `crypto.ts`. The rejection-loop counter is encoded as an explicit
big-endian uint16 (`[...info, counter >> 8, counter & 0xff]`) instead of a
truncating single byte, so a pathological counter rollover can no longer
silently repeat derivations.

## Breaking changes for consumers

1. `addComplaint` returns `boolean` (was `void`). Ignoring the return value
   is safe; gating on it is the recommended new behavior.
2. `DkgComplaint` requires `encryptedShareEventId`. Complaint events without
   `['share', id]` (author = victim) are structurally invalid.
3. `restoreFromBackup` is stricter: backups must carry full, consistent
   VSS commitment sets for the session's threshold; legacy relaxed backups
   are rejected (fail-closed). Use `buildBackupPayload` (unchanged) or the
   certified `courtRecovery` module for new backups.
4. Legacy NIP-59 unwraps now verify; wraps that do not verify return `null`.
