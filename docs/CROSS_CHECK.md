# BAO Court — Cross-Check: every claim, verified in one place

**Version:** tracks `@bao/court` v0.10.2 · **Date:** 2026-11-10 · **Round:** 14 (re-verified round 17 — final polish)
(symposium deep cross-check)

This is the single artifact a reviewer uses to verify any claim about the
system. Every meaningful claim from the three claim sources —

1. `docs/FORMAL_INVARIANTS.md` — all 149 `INV-*` invariants;
2. `docs/FROST_COURT_ORACLE_PAPER.md` — every technical claim (the §6–§7
   universal-confirmation / cohort / batch sections **and** the classic
   ceremony, escrow, and settlement-rail sections);
3. `docs/CRYPTO_AUDIT.md` §7 — the security-argument skeleton (plus the §8
   finding dispositions, which are claims about what is enforced today);

— carries the **verification pointer that proves it TODAY on `main`**: the
exact test (file + test name), bench (bench id), model-check instance
(script + instance + committed fixture), parity check, or an explicit entry
in the **Gap register** when no executable proof exists. Where a claim has
multiple proofs (invariant test + adversarial test + property test), all are
listed.

**Machine-checkable:** § "Machine-checkable index" at the end of this file is
parsed by `scripts/cross-check.mjs`, which verifies that every cited test
name, bench id, model-check instance, and fixture key actually exists — the
doc itself is testable:

```bash
node scripts/cross-check.mjs     # exit 0 = every pointer resolves
```

Conventions for evidence refs:

- `test:<file>#<name substring>` — the test name appears in that file today;
- `bench:<file>#<bench id>` — the benchmark is registered in the bench;
- `model-check:<instance name>` — the instance exists in the committed
  fixture (`__fixtures__/model-check-summary.json`, regenerated by
  `npx tsx scripts/model-check.mjs`) or in `__tests__/modelCheckingCore.ts`;
- `fixture:<file>#<key>=<value>` — the committed fixture asserts that value;
- `doc:<file>` / `script:<file>` — the pointer exists (used for documented
  assumptions and recorded verification runs);
- `pkg:<name>@<version>` — package.json pins that dependency version;
- `gap` — no executable proof; the claim id MUST appear in the Gap register.
